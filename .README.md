# AdventureWorks Sales Analytics Dashboard
### End-to-end Power BI project built on 121,253 transaction records across $109.8M in revenue

---

## Project Overview

This project is a fully end-to-end Business Intelligence solution built entirely in **Microsoft Power BI**, covering every stage of the analytics pipeline — from raw data ingestion and ETL transformation through to data modeling, DAX measure development, and professional dashboard design.

The dataset is the **AdventureWorks Sales Excel workbook** — a realistic multi-table retail dataset representing a bicycle company operating across 6 countries, 2 sales channels (Internet and Reseller), and 4 product categories. The data spans **July 2017 to June 2020** and contains over 121,000 transaction records.

This project demonstrates skills across the full Power BI stack including Power Query (ETL), star schema data modeling, advanced DAX, Row-Level Security, What-If parameters, AI visuals, and Power BI Service publishing.

## Data Model — Star Schema

The data model follows a **star schema** design with `fact_Sales_Enriched` as the central fact table surrounded by 5 dimension tables.

| Relationship | From | To | Key | Cardinality |
|---|---|---|---|---|
| 1 | fact_Sales_Enriched | dim_Date | OrderDateKey | Many → One |
| 2 | fact_Sales_Enriched | dim_Products | ProductKey | Many → One |
| 3 | fact_Sales_Enriched | dim_Customers | CustomerKey | Many → One |
| 4 | fact_Sales_Enriched | dim_Resellers | ResellerKey | Many → One |
| 5 | fact_Sales_Enriched | dim_Territories | SalesTerritoryKey | Many → One |

**Modeling decisions:**
- All foreign key columns hidden from Report view
- `dim_Date` marked as official date table on `DateKey_Parsed` column
- Staging queries (`fact_Sales`, `fact_SalesOrders`) have load disabled
- `fact_Sales_Enriched` created by merging Sales + SalesOrders on `SalesOrderLineKey` to bring `Channel` into the fact table

## DAX Measures

All measures live in a dedicated `_Measures` table for clean organisation.

### Core KPIs
```dax
Total Revenue = SUM(fact_Sales_Enriched[Sales Amount])

Total Cost = SUM(fact_Sales_Enriched[Total Product Cost])

Total Profit = [Total Revenue] - [Total Cost]

Profit Margin % = DIVIDE([Total Profit], [Total Revenue], 0)

Total Orders = DISTINCTCOUNT(fact_Sales_Enriched[SalesOrderLineKey])

Avg Order Value = DIVIDE([Total Revenue], [Total Orders], 0)

Total Customers =
CALCULATE(
    DISTINCTCOUNT(fact_Sales_Enriched[CustomerKey]),
    fact_Sales_Enriched[CustomerKey] <> -1
)
```

### Channel Analysis (B2B vs B2C)
```dax
Internet Revenue =
CALCULATE([Total Revenue], fact_Sales_Enriched[Channel] = "Internet")

Reseller Revenue =
CALCULATE([Total Revenue], fact_Sales_Enriched[Channel] = "Reseller")

Internet Revenue % = DIVIDE([Internet Revenue], [Total Revenue], 0)
```

### Time Intelligence
```dax
Revenue YTD =
TOTALYTD([Total Revenue], dim_Date[DateKey_Parsed])

Revenue Prev Month =
CALCULATE([Total Revenue], DATEADD(dim_Date[DateKey_Parsed], -1, MONTH))

MoM Growth % =
DIVIDE([Total Revenue] - [Revenue Prev Month], [Revenue Prev Month], 0)

Revenue Prev Year =
CALCULATE([Total Revenue], SAMEPERIODLASTYEAR(dim_Date[DateKey_Parsed]))

YoY Growth % =
DIVIDE([Total Revenue] - [Revenue Prev Year], [Revenue Prev Year], 0)
```

### Advanced DAX
```dax
Revenue Rank =
RANKX(ALL(dim_Products[Product]), [Total Revenue],, DESC, DENSE)

Top 10 Product Flag =
IF([Revenue Rank] <= 10, "Top 10", "Other")

Cumulative Revenue =
CALCULATE(
    [Total Revenue],
    FILTER(
        ALL(dim_Date[DateKey_Parsed]),
        dim_Date[DateKey_Parsed] <= MAX(dim_Date[DateKey_Parsed])
    )
)

Discounted Revenue =
[Total Revenue] * (1 - 'Discount %'[Discount % Value])

Revenue Lost to Discount =
[Total Revenue] - [Discounted Revenue]

Discounted Profit =
[Discounted Revenue] - [Total Cost]
```

## 🔒 Advanced Features

Two roles implemented to demonstrate enterprise data governance:

| Role | DAX Filter | Purpose |
|---|---|---|
| `Territory Manager` | `[Region] = USERPRINCIPALNAME()` | Production role — filters to logged-in user's region |

### What-If Parameter — Discount Scenario
- Parameter: `Discount %` (0% to 30%, increment 1%)
- Connected measures: Discounted Revenue, Revenue Lost to Discount, Discounted Profit
- Allows real-time scenario analysis of pricing decisions

### AI Visuals
- **Key Influencers:** Automatically identifies factors driving high/low Profit Margin %

## 💡 Key Learnings & Design Decisions

**Why merge fact_Sales and fact_SalesOrders in Power Query rather than with a DAX relationship?**
Merging in the ETL layer (Power Query) is more efficient than managing a second fact table relationship — it reduces model complexity, eliminates ambiguous filter paths, and makes the `Channel` column a native attribute of the fact table rather than a bridged dimension.

**Why use DIVIDE() instead of the / operator for all ratio measures?**
`DIVIDE(numerator, denominator, 0)` handles divide-by-zero gracefully by returning the alternate result (0) instead of crashing the visual. This is critical when visuals show filtered subsets where the denominator can legitimately be zero.

**Why DISTINCTCOUNT for Total Orders instead of COUNT?**
Each row in `fact_Sales_Enriched` is an order *line item*, not a complete order — one order can contain multiple products. `DISTINCTCOUNT(SalesOrderLineKey)` collapses duplicates to count actual unique orders, while `COUNT` would inflate the number by counting every line.

**Why is dim_Date built from a DateKey integer (20170701) rather than a native date column?**
The source dataset uses integer surrogate keys for dates — a common pattern in enterprise data warehouses and ERP systems like SAP. Parsing these in Power Query (converting integer → text → date) mirrors real-world ETL work on production systems.
